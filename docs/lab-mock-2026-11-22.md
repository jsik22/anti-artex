- **관찰**: UA는 브라우저 값인데 헤더는 Go(`Host, User-Agent, Accept-Encoding`)·Python urllib 기본 모양 그대로였다. 1회차에서 포크 비교로 세운 가정이 실제 변형 트래픽에서 맞았다. Snort 3도 같은 결과다.

### 영문 재배포판(v0.7.0)

- **관찰**: 기본값에서는 도구 UA(`norma/0.4`, `spa-api-recon`)가 그대로라 공개 UA 룰이 통한다.
- **관찰**: 소음 조절(quiet·balanced)을 켜도 경보는 off와 같았다. 바뀐 것은 동시 연결 수(최대 4 → 1~2)뿐이다. 이 기능은 ARTEX 자체 HTTP 요청만 늦추고, 워커가 셸에서 부르는 도구의 속도는 모델이 지시문을 따를 때만 바뀐다(가짜 모델로는 재현 불가).
- **관찰**: WebFetch 헤더에 `Connection: close`가 더 붙는다. UA까지 바꾼 변형이 나오면 헤더 3개 정확 일치 룰(9278394)은 놓친다.
- **관찰**: 기록 프록시(traffic_capture)를 켜면 두 계열 모두 셸 도구 요청에 `Proxy-Connection: Keep-Alive`가 남아 표적까지 간다. 프록시가 요청을 다시 쓰면서 urllib 헤더 순서도 사라진다(9278395가 놓침).
- **관찰**: 이미지에 든 스캐너의 요청 모양

## 한계

- 가짜 모델이라 모델이 고르는 전술·속도는 재현하지 않는다. 공개 보고(Datadog 등)에 나온 UA 일부(`artex-pentest/1.0` 등)는 두 계열 소스 어디에도 없어, 모델이 명령에 넣은 값으로 보인다(추론).
- 정상 표본은 1회차의 두 캡처뿐이다. `Proxy-Connection`은 오래된 프록시가 흘리는 경우가 있어 사냥 용도로 쓴다.
- 발견 재검증(운영자가 콘솔에서 시작)과 bbot(인터넷 필요)은 재지 않았다.
